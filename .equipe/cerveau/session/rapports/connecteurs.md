## Vérifié
- Licences : extract-msg **GPL-3.0** (usage interne local, non redistribué ; pas de problème tant qu'on ne distribue pas le logiciel), RTFDE LGPL-3.0, msal / msal-extensions / faster-whisper / ctranslate2 / onnxruntime / tokenizers MIT, av BSD-3. Modèles Whisper MIT.
- Roues PyPI : ctranslate2 4.8.2, av, onnxruntime, tokenizers ont des roues **win_amd64** (cp311/cp312) et macOS arm64 ; macOS Intel : ctranslate2 et tokenizers oui, onnxruntime 1.30 non (pip prendra une version antérieure, sinon repli). Installation `--user` possible (aucun binaire système requis ; PyAV embarque FFmpeg).
- `.msg` : fichier Outlook authentique fabriqué par le test (écrivain OLE d'extract-msg, propriétés MAPI, pièce jointe) ; fichiers publics du dépôt `TeamMsgExtractor/msg-extractor` (commit 18172ea) lus à la main : `unicode.msg` (2 pièces TIF extraites), `multi-to.msg`, `strangeDate.msg` ; `unicode-header.msg` fait planter extract-msg (gb2312) → l'ingesteur replie sur lecture par le modèle.

- Microsoft : `initiate_device_flow` réel accepté pour l'application par défaut avec nos scopes (code reçu, `https://login.microsoft.com/device`). Faux Graph : aucune requête `send/sendMail/forward/reply`, brouillon créé (createReply + PATCH), synchro idempotente, objets rattachés (Rochat → C-001, Lémantech), l'initiative les collecte.
